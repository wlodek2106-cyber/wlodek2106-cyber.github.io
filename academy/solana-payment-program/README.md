# Zer0Life 95/5 payment program — isolated prototype

**NOT DEPLOYED. DO NOT USE WITH REAL FUNDS.** No program ID/keypair, no build/deploy command in production, and no change to the Python gateway or its disabled release guard.

The experimental native Rust program uses a canonical, permanent PDA with seeds zrl-paid-v1, payer, invoice reference. It checks the payer signature, the fixed mainnet USDC mint, the configured course treasury, exact SPL token owners, account uniqueness, initialized accounts and integer cents. A successful call allocates a receipt and transfers 95% and 5% directly from payer to the two recipients, in one atomic transaction. A second call with the same program, payer and reference fails before any transfers if the receipt already exists. Pre-funded empty system-owned PDAs are handled via top-up/allocate/assign. There is no receipt close or withdrawal instruction. The payer pays rent and network fees in SOL, in addition to the quoted USDC.

ABI: 73 bytes: version 1, reference pubkey (32), freelancer owner pubkey (32), unsigned cents (8 little-endian). Exactly eight accounts: payer signer+writable, receipt PDA writable, payer USDC writable, freelancer USDC writable, treasury USDC writable, mint readonly, SPL token executable readonly, system program executable readonly. Receipt: version byte, payer, reference, freelancer owner, cents (105 bytes).

This only prevents a second payment through this same program for the same fixed payer/reference; ordinary SPL transfers and alternate programs can bypass it, and another payer would have another PDA. Invoice authorization is off-chain: the payer can intentionally consume their own reference with wrong terms, which the future verifier must reject, requiring support. No server signing or escrow. A permanent receipt needs rent; upgrades or redeployment affect guarantees. No production acceptance of this program yet.

Next gates: cargo test host suite (not a Solana runtime test); lock dependency tree, SBF build, local validator tests with synthetic mint/test-only configuration for success, replay under a new blockhash, pre-funded PDA, rollback when either transfer fails, wrong mint/accounts/amount, concurrency, insufficient SOL/USDC and malformed data. Then independent review, fixed audited program ID and upgrade authority policy, new gateway builder and finalized receipt/CPI verifier bound to original invoice, wallet compatibility, support/duplicate recovery and legal review. Do not remove production release blockers simply because host tests pass.
