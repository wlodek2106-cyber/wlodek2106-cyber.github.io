# Academy local backup and recovery
Zero-cost software: PostgreSQL client tools, GnuPG and local Docker (or compatible Docker engine). Requires local disk and compute. No backup stored in GitHub or Render filesystem. No production database URL or actual backup was obtained by this development update.
1. Install a compatible PostgreSQL client (pg_dump version must be at least the source server major version), GnuPG and a local Docker engine. Restore uses PostgreSQL 17; if the source is newer, update and test the restore image first. Set GPG_TTY to the terminal if needed. Use a direct Academy database connection, not a transaction pooler. Use read-only credentials with sufficient schema permissions if available.
2. Set ACADEMY_DATABASE_URL in your private local shell, not in a GitHub issue or chat. Run: bash academy/ops/backup.sh. GPG prompts for a strong passphrase. Store it separately. Keep at least two encrypted copies in separate trusted locations. Do not commit archives or secrets. Set a retention schedule appropriate to applicable privacy and financial obligations.
3. Run: bash academy/ops/verify_restore.sh /path/to/academy-TIMESTAMP.dump.gpg. Requires an explicitly local Docker Unix socket; on macOS set ACADEMY_LOCAL_DOCKER_SOCKET to the local engine socket if needed. No production restore is supported. The temporary container is deleted on exit; its local storage may not be securely erased, so use an encrypted local disk. Compare counts and separately test an application using synthetic data. Successful verification is not a disaster recovery certification.
4. Record backup date, checksum, restore date and result privately. Test after schema changes. Source code alone is not a database backup. Do not claim a backup exists until the actual encrypted archive has been created and tested.
5. Before commercial launch agree incident response, recovery target, storage retention and owner authority. No automated cloud upload, no paid service, no production restore endpoint.
