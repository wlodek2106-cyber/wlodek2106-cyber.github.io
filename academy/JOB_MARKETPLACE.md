# Academy Job Marketplace
Academy accounts: free registration for clients, paid enrollment for applications. Owner moderation before posting; signed-in feed, personal posts and applications, single selected freelancer, private contact disclosure after selection, delivery and acceptance status. 0% platform fee; external payment and contract only, no escrow, arbitration, automatic matching, payment guarantee, reviews or jobs seeded as real. Do not include contact or secrets in brief/proposal. Limits: 30 posts per account, 100 applications per student, 50 per job. Separate Zer0Life Freelance repository remains a scaffold; no cross-service SSO/sync. Privacy export contains own records only. Tests added; actual deployment and customer demand require verification.

## Client entry and recommendations
Public /hire page with four languages and free client registration CTA, no public job or private data exposure. Existing account authentication continues to be required. Recommendations use completed lesson categories and approved service category only; exclude own posts and previous applications, rank at most 300 recent eligible jobs and return 30 matches. No AI inference or paid API, no automated outreach or guaranteed availability. Course milestones do not certify practical competence. Actual acquisition requires genuine client outreach.

## Organic client acquisition
Share /hire?lang=en&src=telegram (or instagram, youtube, linkedin, facebook, tiktok, x, partner, other, direct). First new registration through the post-project CTA stores an allowlisted label, no tracking cookie, click tracking or payout. No retroactive attribution or existing-account tracking. Owner-only report includes all-time registrations, unique accounts with posted jobs, jobs by current status, applications and conversion into any posting client. Counts include pending/rejected/cancelled posts; not verified customers or payments. CSV and copy links. Own source included in privacy export. The existing referral and commission rules remain untouched. Campaign links are not individualized referrals and labels can be self-selected. No outreach performed.

## Reputation
Client may submit one 1–5 rating and optional comment for a completed job. Owner approves/rejects or hides approved reviews. Only approved ratings count; approved text is visible to the selected freelancer, not public. Applicant explicitly opts in per application to sharing aggregate rating, approved review count, completed recorded jobs, passed lessons and certificate-issued status with the posting client. Existing applications default to no sharing. No private profile, exam scores, certificate codes, other job descriptions or contact exposure from reputation. Job history is private to selected freelancer. No payment validation, identity proof or collusion guarantee; no claim of real-world skill certification. Own privacy exports include written/approved received reviews. No fees.

## Project room
After selection only the client and selected freelancer can access room endpoints (owner has no special room access). Text messages, manual refresh, 50/page, 500 ordinary messages, 550 total records with delivery/revision reserve, up to 20 client-created milestones; freelancer marks done, client can reopen. Delivery notes and client revision requests change order state atomically; acceptance via existing complete action. Milestones are advisory, not payment milestones or prerequisites. Completed rooms are read-only. Legacy deliver endpoint remains compatible, so old clients may mark delivery without notes. No attachments, clickable external links, realtime notifications, end-to-end encryption or payment custody. Own authored messages and created milestones included in privacy export. No new paid API. Tests use rollback-only synthetic data.

## Notification Center
Authenticated inbox for client moderation, new applications, selection, project messages, delivery, revision, completion and approved reviews. Events are inserted in the same transaction as the change; only recipient can list or mark read. No message body or contact in notifications. 30/page, 90-day visibility, 500 recent records retained per recipient on new event; no retroactive backfill. Manual refresh and visible-tab badge check every 90 seconds, plus current recommended-jobs count (up to 30, not an alert broadcast). No email, push, Telegram, real-time WebSocket or paid API. Only safe existing dashboard routes are opened. Read state is included in own data export. Rollback-only tests verify events and recipient isolation.

## Freelancer Analytics
Private paid-student report, 7/30/90 UTC-day application cohorts, all-time overview, current statuses, selected and completed proposal values in USD cents, selection rate and completion among selected, category breakdown, daily application bars, existing reputation and CSV export. Cohorts measure submission date, not completion dates; amounts are agreed proposal values only, never verified revenue. No new storage, tracking or external AI. No third-party account identifiers in the response. Tests cover zero denominators, cohort boundaries, permission and actual synthetic completion.

## Freelancer Business Manager
Selected freelancer can explicitly copy an assigned, delivered or completed job into existing private CRM, selecting own existing client or entering a new client name. Uses chosen proposal amount, zero recorded receipts/expenses, and no contact copy. Unique source-job index and student lock prevent duplicate imports; repeat import leaves manual edits untouched. Deleting private order permits reimport. Source job deletion detaches reference without deleting financial record. Snapshot status is not synchronized. Per-order cash margin and estimated contract margin, numeric/status CSV, existing private JSON and commercial proposal PDF (draft, not tax invoice). No transfers, payment proof, tax calculations or paid API. Source IDs included in own privacy export. Tests cover access, idempotence and manual amounts.

## Marketplace USDC split — staged, not enabled
5% of the selected quote in native SPL USDC on Solana mainnet to the existing course TREASURY, 95% to selected freelancer. Integer atomic amounts (1 USD cent = 10000 USDC atomic units), no custody or server keys. `ACADEMY_MARKETPLACE_PAYMENTS_ENABLED` must remain unset/false until wallet transaction construction, signing compatibility, duplicate-payment controls, independent security review, legal review and authorized end-to-end testing. Existing jobs retain external mode; only newly posted jobs after activation would be split. Owner Treasury reports verified DB records, not chain wallet balance. Preview is read-only. Staged backend freezes payer/recipient and reference per job, validates exact finalized legacy outer SPL TransferChecked instructions and token-account owner balance changes, rejects wrong amounts, distinct-wallet failures, inner instructions and replay via unique signature. No transaction construction, public payment links or submission UI in this stage; do not send funds manually. Completion of split-mode jobs requires verified payment; do not turn on flag before full signing workflow exists. No actual payment, wallet proof, customer escrow or automatic payout. External RPC may have limits. Legal and dispute terms still require review.

## Solana Pay transaction request (disabled until independent review)
The same-origin fixed HTTPS GET/POST endpoint returns label/icon or an unsigned legacy transaction (zero blockhash for wallet replacement under Solana Pay spec). Two TransferChecked instructions, one payer signer, exact six-decimal USDC, existing initialized source and destination token accounts only; no ATA creation, server signature, or broadcast. Authenticated client QR uses opaque invoice reference, 15-minute issuance window and payer binding. One-time server issuance uses job lock; no automatic reissue. Once an invoice exists revision is blocked to avoid payment race; reconciliation is required after abandonment or expiry. This does NOT prevent a wallet from independently re-signing with a new blockhash or paying twice; no on-chain idempotency program. User must not retry before reconciliation. Wallet compatibility, independent review, duplicate-payment reconciliation, support process and legal review remain blockers; keep ACADEMY_MARKETPLACE_PAYMENTS_ENABLED false. No mainnet transfer performed. Spec: https://docs.solanapay.com/spec

## Read-only reconciliation and duplicate warnings
Authorized parties or owner can inspect up to four recent finalized reference signatures (RPC requests capped at 2-second socket timeout each). Every candidate must pass the exact 95/5 transfer verifier using issuance time, not invoice creation time. Multiple matching payments, including matches different from a recorded signature, are flagged. Missing/limited/failed scans never authorize retry. No automatic payment or reissue, and no auto-refunds. Client can submit recovered signature via existing confirmation; owner cannot credit or move funds through reconciliation. Existing issued requests remain reconcilable and confirmable when new payment issuance is disabled. Worker preview no longer exposes the payment request reference. Treasury displays latest 100 unsettled requests. This is not complete chain-history auditing or on-chain double-payment prevention; independent wallet and security testing remain required. Corrected byte-offset expectations in unsigned-transaction unit test.

## Payment lifecycle integration checks
Synthetic rollback-only coverage now exercises enrollment and marketplace job selection, wallet authorization, delivery, blocked completion, invoice creation and cancellation before issuance, QR, payer binding, single issuance, finalized-reference scan, invalid transfer rejection, correct settlement while checkout closed, idempotent confirmation and exact 5% treasury delta. RPC/build fixtures replace network, never sign or broadcast; temporary payment tables avoid touching actual financial records. Transaction unit test decodes instruction fields instead of guessed byte offsets. Client can cancel a request only before issuance; server job lock prevents cancellation races. No on-chain idempotency, live wallet compatibility or real fund test. Keep payment flag disabled. 

## Fail-closed release guard
The environment flag alone cannot enable new split orders or payment requests while `marketplace_release.BLOCKERS` is nonempty. The owner-only Treasury preflight checks existing initialized USDC accounts via configured RPC, no transfer or signing, and discloses lack of independent network verification. The release gate is not a certification or a substitute for on-chain duplicate protection. Existing issued requests can still be confirmed/reconciled when issuance is closed. Additional SQL diagnostics flag inconsistent split records. Synthetic integration locally patches enabled for its fixture only.

Keep both paths separate and the release guard closed. Offline fixture tests are not an audit or proof of mainnet compatibility.
