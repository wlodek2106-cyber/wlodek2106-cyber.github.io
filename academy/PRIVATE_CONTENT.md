# Private curriculum migration

The public repository and its history contain the legacy curriculum and exam answers. They cannot be made secret by deleting a file. Do not reuse those questions as a secure assessment.

Owner-only Private Curriculum accepts one new lesson or exam bank at a time, in JSON (request limit 16 KiB). Data is written to the existing Academy database, not GitHub. Every upload is versioned by revision number and the change is audited. Only the latest version is kept, not a full revision history. Student endpoints return lesson content only after enrollment/unlock checks; exam endpoints sample and shuffle questions without correct answers. The tutor uses the replacement lesson when available.

Populate original, independently reviewed banks for all 45 days in English, optionally add RU/UK/PL variants. Missing translations fall back to English. After verifying coverage, owner may enable ACADEMY_PRIVATE_EXAMS_REQUIRED=true and ACADEMY_PRIVATE_LESSONS_REQUIRED=true on Render. Without coverage, strict mode blocks the corresponding missing lessons/exams; do not enable prematurely. Existing public content, existing attempts, agent-lab and Pro library are not retroactively made private. Database encryption at the application level is not implemented. Never place new answer banks in public Git commits.

## Legacy question guard and coverage
New private exam uploads reject normalized exact matches against the bundled public exam banks (including lesson 1 translations), as well as normalized duplicates. Strict exam reads reject known legacy matches. Inventory exposes counts and missing slots for each language, plus known overlap counts, never answer content. It does not detect paraphrases or every historical copy; independent review remains essential. Strict configuration remains unchanged; no actual private material is committed or uploaded by this update. Existing public legacy resources remain public. English full coverage and no known legacy matches are necessary but not sufficient for commercial readiness.

## Private bulk import
Owner dashboard accepts a local JSON bundle `{version:1,items:[{kind,day,lang,content},...]}` (up to 360 slots, 4 MB, 16 KiB per serialized request). After confirmation, sequential authenticated requests create missing slots only; database ON CONFLICT DO NOTHING prevents overwrites even during concurrent uploads. Stop after current request or resume by importing the same file. Existing manual save can still update individual slots. Import is not an atomic transaction; inspect inventory after partial failures. Keep the file offline and never publish it to Git. Review contents before importing, and do not enable strict mode until verified. No paid API.

## Preflight and startup isolation
The owner can validate a selected bundle without saving any slots. Each entry goes to the authenticated `/admin/content/validate` endpoint, checking exact schema, encoding, limits and legacy exam matches, without content-table writes. Optional preflight is not a pedagogical review, atomic import or strict-mode activation. Startup integration now uses temporary private-curriculum and audit tables for synthetic tests instead of real owner slots; rollback removes them. Existing owner materials are never overwritten by these tests.
